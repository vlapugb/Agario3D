# Agario 3D

Одиночная игра на C++23 и Huynity. В быстром матче за три минуты нужно собрать больше массы, чем пять ботов. Каждая клетка может подбирать еду, поглощать соперников и быть съеденной отдельно.

## Сборка и запуск

Нужны CMake 3.20+, Ninja, компилятор C++23 с поддержкой `std::expected`, библиотеки разработки SDL3 и OpenGL. Для игры требуется графическая сессия с OpenGL 3.3 Core.

Из корня **Agario3D** с локальным checkout движка в `../Huynity` выполните

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DHUYNITY_SOURCE_DIR=../Huynity
cmake --build build --target agario3d -j2
./build/agario3d
```

Если движок лежит в другом каталоге, передайте его путь в `HUYNITY_SOURCE_DIR`. Получить checkout для новой установки можно командой `git clone --branch master https://github.com/vlapugb/Huyunity.git ../Huynity`. Сборка кладёт атлас шрифта `hud.bmp` рядом с исполняемым файлом.

## Пакетирование

Из корня репозитория одна команда собирает все пакеты для Linux и Windows x86_64 в `dist/`. Нужны Docker с Buildx, локальный checkout движка и доступ к сети при первой сборке.

```sh
./packaging/build.sh
```

По умолчанию сборка берёт движок из `../Huynity`. Для другого checkout выполните `HUYNITY_SOURCE_DIR=/путь/к/Huynity ./packaging/build.sh`. Версия пакетов задаётся в `project(... VERSION ...)` в корневом `CMakeLists.txt`.

| Пакет | Как установить и запустить |
| --- | --- |
| Linux AppImage | `chmod +x dist/*.AppImage`, затем `./dist/Agario3D-0.1.0-linux-x86_64.AppImage`. Если FUSE недоступен, добавьте `--appimage-extract-and-run` |
| Linux ZIP | Распакуйте архив и запустите `./AppRun` из распакованной папки |
| Debian DEB | `sudo apt install ./dist/agario3d_0.1.0_amd64.deb`, затем `agario3d` |
| Fedora RPM | `sudo dnf install ./dist/agario3d-0.1.0-1.x86_64.rpm`, затем `agario3d` |
| Windows EXE | Откройте установщик и запустите **Agario 3D** из меню «Пуск» |
| Windows ZIP | Распакуйте архив целиком и откройте `agario3d.exe` |

AppImage и Linux ZIP включают SDL3. Для них нужны glibc 2.38 или новее и системные библиотеки OpenGL с поддержкой OpenGL 3.3 Core. DEB и RPM получают SDL3 из репозитория дистрибутива. В обе Windows-сборки включены DLL и атлас HUD.

## Управление

«Быстрый матч» сразу открывает арену. В разделе «Создать сессию» можно ввести ник до 16 символов, выбрать цвет по предпросмотру, длительность 3, 5 или 10 минут и от 0 до 8 ботов. При нуле ботов на арене остаются еда и колючки. В меню работают мышь, стрелки и Enter.

В настройках доступны оконный и полноэкранный безрамочный режимы, VSync, чувствительность мыши от 0,25 до 2,0× и инверсия Y. «Применить» сохраняет выбор в `settings.ini` в пользовательском каталоге настроек SDL для Huynity/Agario3D. «Отмена» возвращает в меню.

| Ввод | Действие |
| --- | --- |
| Мышь | Повернуть взгляд по горизонтали и вертикали |
| Удерживать W | Разогнаться по направлению взгляда. Полный разгон занимает 5 секунд |
| Отпустить W | Затормозить. С максимальной скорости до остановки проходит 2 секунды |
| Space | Разделить клетки массой от 36. Нечётная единица достаётся выброшенной половине |
| Enter или R на экране результата | Начать новый матч с теми же параметрами |
| Esc в матче | Поставить игру на паузу и освободить курсор. Повторное нажатие продолжает матч |

Предел общей тяги зависит от суммарной массы всех ваших клеток `M` по формуле `5,8 × (40 / M)^(1/4)` в диапазоне 2,61–7,83 ед/с. При 40 единицах это 5,8 ед/с, при 80 — 4,88, при 160 — 4,10. Деление сохраняет предел группы. HUD показывает текущую скорость в ед/с и процент от этого предела.

На полном ходу после затухания импульса половины держат дистанцию. При торможении лёгкие пары стягиваются быстрее тяжёлых. Для слияния нужны контакт, скорость ниже 30% и истёкшие таймеры обеих частей. Таймер каждой части равен `12 + 0,15 × масса при образовании` секунд. Длительность перетекания фиксируется в момент контакта по формуле `0,6 × √((m₁ + m₂) / 40)` в диапазоне 0,3–2,4 секунды. Две части по 20 сливаются за 0,6 секунды, две по 80 — за 1,2 секунды.

За каждую игровую минуту без еды участник теряет 10% текущей массы. Например, 200 единиц превращаются в 180, а через следующую минуту — в 162. Потери распределяются пропорционально массе частей, дробный остаток переносится при делении, слиянии и поглощении. У каждой живой клетки остаётся минимум одна единица. В паузе расход останавливается.

Колючку можно задеть по касательной. Задетые иглы пригибаются, оставляют вмятины на оболочке и слегка притормаживают коснувшуюся их клетку. Остальные части продолжают полёт своим ходом. Клетка легче 100 проходит даже сквозь ядро. Если к началу контакта клетка набрала хотя бы 100, попадание в ядро добавляет ей 100 массы и разрывает её максимум на четыре части. Лобовой удар даёт более сильный разлёт, при косом сохраняется скольжение вдоль поверхности. При 15 клетках получаются две части, при 16 колючка остаётся на арене.

Чтобы наползти на соперника близкой массы, держите W и направьте прицел немного в сторону от его центра. Край вашей клетки растечётся по его боку, а при повороте в сторону от соперника отлипнет. В невесомости это работает с любой стороны. Если масса охотника достигает 1,25 массы добычи, он поглощает её при входе её центра внутрь своей клетки.

При потере последней клетки открывается таблица с возможностью сразу начать заново. Боты доигрывают до конца выбранного времени. При равной массе участники делят место. «Ещё раз» на паузе или в итогах восстанавливает стартовую массу, расстановку и таймер в том же окне.

## Проверка

```sh
cmake --build build -j2
ctest --test-dir build --output-on-failure
ctest --test-dir build -V -R '^agar_match$'
```

Последняя команда печатает мировые координаты клеток после деления и торможения, длительность слияния лёгкой и тяжёлой пары, убыль массы за две минуты и прогиб оболочки при контакте. Тест сравнивает убыль и столкновения при 30, 60 и 120 кадрах/с. Тест `agar_session` проверяет ввод ника, настройки, паузу и перезапуск через те же обработчики, что используются в окне игры.
